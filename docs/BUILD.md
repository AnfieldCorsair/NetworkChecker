# Сборка из исходников — пошагово, для тех, кто делает это впервые

Задача: получить из папки с исходниками работающий `NetworkChecker.exe` на своём компьютере.
Понадобятся только Windows 10/11, интернет и 10–15 минут. Программировать не нужно.

---

## Шаг 0. Что понадобится

| Что | Зачем | Сколько весит |
|---|---|---|
| Windows 10 или 11 (64-бит) | приложение заточено под Windows | — |
| .NET 10 SDK | компилятор и рантайм для сборки | ~300 МБ |
| Папка с исходниками | сам проект | ~1 МБ |
| Интернет | один раз скачать пакеты NuGet | ~50 МБ трафика |

Ничего больше ставить не надо: ни Visual Studio, ни Git (он пригодится только если хотите обновлять проект через `git pull`).

---

## Шаг 1. Поставить .NET 10 SDK

Откройте **PowerShell** (кнопка «Пуск» → наберите `PowerShell` → Enter) и вставьте одну строку:

```powershell
winget install Microsoft.DotNet.SDK.10
```

Если `winget` нет (старая сборка Windows) — скачайте установщик вручную:
<https://dotnet.microsoft.com/download/dotnet/10.0> → **SDK 10.x** → **Windows x64 Installer** → установить с настройками по умолчанию.

**Закройте окно PowerShell и откройте заново** (без этого команда `dotnet` не найдётся) и проверьте:

```powershell
dotnet --version
```

Должно вывести что-то вида `10.0.403`. Если пишет «не является внутренней или внешней командой» — смотрите [раздел «Если что-то пошло не так»](#если-что-то-пошло-не-так).

---

## Шаг 2. Получить исходники

**Вариант А (без Git):** откройте страницу проекта на GitHub → кнопка **Code** → **Download ZIP** → распакуйте в удобное место, например `C:\src\network-checker`.
Важно: распаковать, а не запускать из ZIP-архива.

**Вариант Б (с Git):**

```powershell
git clone https://github.com/AnfieldCorsair/NetworkChecker.git C:\src\network-checker
```

Дальше считаем, что проект лежит в `C:\src\network-checker`.

---

## Шаг 3. Собрать одной командой

В PowerShell перейдите в папку проекта и запустите скрипт сборки:

```powershell
cd C:\src\network-checker
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Publish
```

Что произойдёт по шагам (скрипт сам всё сделает и напишет в консоль):

1. `restore` — скачает пакеты NuGet (нужен интернет, делается один раз);
2. `build` — скомпилирует проекты решения;
3. `test` — прогонит 245 автотестов (это проверка, что всё собралось правильно);
4. `publish` — соберёт готовое приложение в папку `artifacts\win-x64`.

В конце скрипт напишет:

```
Готово: C:\src\network-checker\artifacts\win-x64\NetworkChecker.exe
```

`-ExecutionPolicy Bypass` в команде — это не «хакерство», а способ разрешить запуск локального
скрипта в текущем окне. Политику безопасности системы команда не меняет.

---

## Шаг 4. Запустить

```powershell
.\artifacts\win-x64\NetworkChecker.exe
```

Или просто откройте `artifacts\win-x64` в проводнике и дважды щёлкните по `NetworkChecker.exe`.

При первом запуске Windows SmartScreen может спросить подтверждение («Неизвестный издатель») —
это нормально для любого самосборного файла без цифровой подписи: **Подробнее → Выполнить в любом случае**.

### Два варианта сборки

| Команда | Размер папки | Нужен .NET на целевой машине |
|---|---|---|
| `.\build.ps1 -Publish` | ~15 МБ | да (тот же .NET 10 Desktop Runtime) |
| `.\build.ps1 -Publish -SelfContained` | ~90 МБ | нет, всё внутри |

Если хотите перенести программу на другой компьютер флешкой — берите `-SelfContained`.

## Шаг 5. Что получилось

В окне приложения:

- переключатель **«Просто / Подробно»** в правом верхнем углу — простой режим показывает понятный
  ответ и шесть фактов, подробный открывает метрики, находки, маршруты и трассировку;
- кнопка **«Проверить компьютер»** — прогон проверки;
- **«Экспорт»** — сохранение отчёта в PDF, Word, Excel, CSV, Markdown или JSON;
- вкладки **Сеть**, **История**, **Справка**, **Настройки**.

Данные приложения лежат локально, в `%LOCALAPPDATA%\NetworkChecker\`:

| Файл | Что внутри |
|---|---|
| `settings.json` | настройки, список целей, выбранный режим интерфейса |
| `history.db` | история прогонов (SQLite) |
| `logs\app-YYYYMMDD.log` | журнал |

Удалить программу «до нуля» = удалить папку `artifacts` и эту папку с данными.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| `dotnet: не является внутренней или внешней командой` | PowerShell открыт до установки SDK | закрыть и открыть PowerShell заново; если не помогло — перезагрузиться |
| `Невозможно загрузить файл build.ps1, так как выполнение скриптов отключено` | политика ExecutionPolicy | запускать ровно так: `powershell -ExecutionPolicy Bypass -File .\build.ps1 -Publish` |
| `error NU1301 ... Unable to load the service index` | нет доступа к nuget.org (прокси, файрвол, VPN) | проверить интернет; при корпоративном прокси — `dotnet nuget list source` |
| `error NETSDK1045: текущий пакет SDK не поддерживает .NET 10` | стоит старый SDK | `dotnet --list-sdks`; поставить .NET 10 SDK по шагу 1 |
| Сборка падает с `CS...` в незнакомом месте | повреждённая распаковка исходников | удалить папку, скачать ZIP заново, распаковать в путь **без пробелов и кириллицы** |
| `Не удалось загрузить файл ... NetworkChecker.exe` при запуске | антивирус сканирует только что собранный файл | подождать 10–20 секунд и запустить снова; при упорстве — добавить папку `artifacts` в исключения |
| Приложение запускается и сразу закрывается | смотрите журнал: `%LOCALAPPDATA%\NetworkChecker\logs\` | в логе будет конкретная ошибка — её можно приложить к issue |
| Хочется запустить тесты отдельно | это же проверка сборки | `dotnet test` в папке проекта |

Если ничего не помогло — приложите к issue **полный текст из консоли** и последний файл из `logs\`.

## Для тех, кто хочет собрать без скрипта

```powershell
cd C:\src\network-checker
dotnet restore
dotnet build -c Release
dotnet test
dotnet run --project src/NetworkChecker.App
```

`dotnet run` — запуск «как есть», без сборки папки с exe (удобно для разработки).
Публикация папки с exe — команда из шага 3 либо:

```powershell
dotnet publish src/NetworkChecker.App -c Release -r win-x64 --self-contained false `
  -p:PublishSingleFile=true -o artifacts/win-x64
```

## Требования и оговорки

- Права администратора не нужны. Без них недоступны raw-ICMP-трассировка (используется fallback
  через `Ping`) и часть данных файрвола другого пользователя.
- Проверки читают только то, что видно без установки драйверов и служб.
- Если ICMP в сети заблокирован, RTT-модуль переключается на TCP и помечает метод измерения.
- Наличие признака ≠ доказательство обхода: у каждого вывода есть уровень серьёзности и объяснение.
