# Проверка сетевого экрана и оценок

## Статус проверки

Проведён разбор кода; автоматические тесты выполняются в Linux, а реальный Windows-запуск с обычными и повышенными правами ещё необходим. Позже по согласованию добавлены UAC-кнопка и экспериментальное наблюдение WFP/ETW; их работа на Windows ещё не проверена, подробности — [OBSERVATION.md](OBSERVATION.md).

### Экран «Сеть»

| Возможность | Реализация и ограничения |
|---|---|
| Адаптеры, шлюз, DNS | .NET NetworkInterface. Обычно читаются обычным пользователем; частичная конфигурация, ошибки и нестандартные адаптеры возможны. Пустой DNS — «не удалось определить», а не доказательство автоматической настройки. |
| Таблица маршрутов | На Windows вызывается PowerShell `Get-NetRoute` для IPv4. Командлет может отсутствовать, истечь по таймауту или вернуть пустой результат из-за политики/доступа; пустой список не означает, что маршрутов нет. Ранее после ошибки пробовали читать Linux `/proc/net/route` на Windows — исправлено. IPv6-маршруты этим методом не получаются. |
| Прокси | Читаются реестр WinINET, предполагаемые данные WinHTTP и переменные окружения процесса. Пустой результат теперь назван «не обнаружен», не доказано отсутствие. Часть ошибок чтения сейчас подавляется платформенным слоем: надёжно различить «не настроен», нет доступа и сбой пока нельзя. Расшифровка машинных бинарных настроек требует проверки на разных Windows; WPAD, политики и прокси отдельных программ могут не учитываться. Исправлено использование сохранённого, но выключенного WinINET ProxyServer и разбор HTTPS-схемы. |
| Внешний IP и STUN | Это обращения к внешним сервисам, не локальные сведения. Отсутствие ответа не означает, что интернета нет; сторонние сервисы видят IP запроса. |
| Задержка, MTU, DNS и TLS | Сетевые запросы; ICMP может блокироваться, а MTU не всегда определяется. DNS fallback обращается к 1.1.1.1; TLS и DoH — к внешним узлам. При включённом офлайн-режиме ручная диагностика не запускается. |
| Трассировка | ICMP, при недоступности raw-сокета — запасной вариант; права могут требоваться для raw ICMP, но не являются единственной причиной ошибки. Хопы могут не отвечать; ASN-запросы тоже сетевые. При включённом офлайн-режиме ручной запуск блокируется. |

Важно: ошибка или отсутствие поддержки конкретного компонента пока не во всех случаях передаётся в UI отдельно от пустого результата. Для корректного различения нужны типизированные результаты каждой пробы (`успех / нет настройки / нет доступа / компонент отсутствует / ошибка`), а затем проверка на Windows. Просто приписать любой ошибке «нужен администратор» было бы неверно.

## Разбор баллов

Обе шкалы — **авторские эвристики**, не проценты, не вероятность обнаружения VPN и не оценки конкретного сайта. Нет размеченной выборки, оценки ложных срабатываний или независимой калибровки, поэтому конкретные цифры и пороги нельзя считать статистически обоснованными.

### Общий вердикт

Патч 1.6 изменил правила: индекс считается по выполненным модулям; при отсутствии данных не выводится. `Detected` означает факт настроенного прокси (включая окружение процесса) или подключённого Windows VPN, но не доказанный маршрут браузера. Все остальные признаки — максимум `NeedsReview`. Разница IP сравнивается внутри семейства и не доказывает split tunneling. Подробная формула — [CHECKS.md](CHECKS.md).

Индекс остаётся некалиброванным и зависит от состава доступных модулей. Старые прогоны не пересчитываются и могут быть несопоставимы с 1.6. Подавляемые Windows-ошибки, специфичные маршруты браузера, локальные API клиентов и реальные сценарии требуют проверки. [Матрица на Windows](WINDOWS_TEST.md).

### «Глазами сайта»

Сейчас метка прокси = 30, хостинг = 25, иностранный IP = 20, разница часовых поясов > 2 ч = 15, несовпадение языка и страны = 10, User-Agent приложения = 5; сумма ограничена 100. Порог 20/50 произвольный. Например, человек за границей с русским языком и клиентом NetworkChecker получит 35 даже без VPN; системный язык и пояс вообще не обязательно совпадают с настройками браузера. Адрес другого государства, язык, часовой пояс и User-Agent программы слабо обосновывают наличие VPN. Метка и хостинг могут быть связаны и ошибочны. Значение `false` не подтверждает достоверность или полноту базы.

Для русского языка в KZ, UA, BY, KG, UZ, TJ, AM, AZ, MD, TM и GE показывается информационное примечание с нулевым весом вместо штрафа за язык. Это не политический перечень СНГ: Украина и Грузия учитываются только как страны, где встречается русский язык. Иностранный IP по-прежнему добавляет 20 баллов. Снижение или удаление остальных весов и смена порогов без данных также было бы произвольным; рекомендуется обсуждение новой модели и тестирование на реальных размеченных сценариях. Экран не воспроизводит алгоритмы ВК, Яндекса или иных сервисов.
