Core не знает про Avalonia и про реестр: всё платформенное спрятано за `IPlatformProbe`. Поэтому Core тестируется на Linux, а весь Windows-специфичный код собран в одном проекте.

## Прогон проверки

1. `DashboardViewModel.RunCommand` создаёт `CancellationTokenSource` и вызывает `CheckRunner.RunAsync(options, privacyMode, ct)` в фоне (`Task.Run`).
2. `CheckRunner` запускает все `ICheck` параллельно через `SemaphoreSlim(MaxParallelChecks)`. Каждый модуль получает общий `CheckContext`: настройки, колбэк прогресса и сборщик IP-наблюдений.
3. Модуль возвращает `CheckResult`: статус (`Clean/NeedsReview/Detected/Skipped/Failed`), находки (`Finding` с уровнем серьёзности и evidence), метрики для плиток, длительность.
4. `IpConsensusBuilder` группирует наблюдения IP по всем модулям: консенсус, голоса «российский/иностранный», признак расщепления.
5. `VerdictEngine.Build` считает взвешенный балл, применяет жёсткие правила и собирает причины.
6. `HistoryRepository.SaveAsync` пишет прогон в SQLite (если включено). UI обновляется через события `Progress`/`StatusText`.

Ошибка одного модуля не рушит прогон: исключение превращается в `CheckResult.Failed`, вердикт помечается как неполный.

## Ключевые абстракции

| Тип | Назначение |
|---|---|
| `ICheck` | модуль проверки: `Category`, `Title`, `Weight`, `RunAsync` |
| `CheckContext` | настройки + прогресс + `CollectIp(...)` |
| `IPlatformProbe` | всё, что зависит от ОС: адаптеры, маршруты, DNS, прокси, приложения, процессы, службы, VPN-профили, hosts, файрвол |
| `IHttpProbe` | HTTP с опцией «игнорировать системный прокси» и честным таймаутом |
| `PacInspector` | разбор PAC-скрипта: какие прокси он задаёт, есть ли loopback и правила по подсетям |
| `RunComparer` | сравнение двух прогонов: статусы модулей, появившиеся находки, направление изменений |
| `PingTools` / `RawIcmp` / `TraceTool` | ICMP-эхо, MTU-проба, трассировка (raw + fallback) |
| `DnsClientLite` / `DnsWire` | запросы к конкретному резолверу, парсер DNS-сообщений, DoH |
| `AsnLookup` | ASN/оператор по IP через DNS Team Cymru |
| `HttpProbe`, `GeoIpParser`, `Masking` | сеть, нормализация GeoIP-ответов, приватный режим |

## Потоки вкладки «Сеть»

`NetworkInfoService` — единственная точка входа для UI:

- `GetOverviewAsync` — адаптеры, маршруты, DNS, прокси (+ внешний IP и STUN, если не офлайн).
- `RunDiagnosticsAsync` — параллельные группы задач: задержки, MTU, DNS-резолверы + DoH, TLS.
- `TraceAsync` — трассировка с построчным `IProgress<TraceHop>` (хопы появляются по мере прохода) и обогащением ASN.

## Хранение

EF Core 10, SQLite, `IDbContextFactory` (короткие контексты на операцию). `DateTimeOffset` хранится как `UtcTicks` — иначе SQLite не умеет сортировать такие значения в SQL. Таблицы: `runs` (плоские поля для списка + JSON-снимок чеков/наблюдений/окружения), `logs`.

## UI

Шесть экранов, навигация — коллекция `NavItem` в `MainWindowViewModel`, контент — `ContentControl` с `ViewLocator`. Все цвета — в `ThemeDictionaries` (`App.axaml`), есть тёмная и светлая темы. Стили-классы: `card`, `chip`, `inset`, `h1..h3`, `muted`, `mono`, `overline`, кнопки `primary/ghost/danger/nav`.

Раскладка адаптивная: карточки модулей в `WrapPanel` (2 колонки на 1440 px, 1 колонка на узком окне), таблицы сети — `Grid` с пропорциональными колонками, минимальный размер окна 1080×720.

## Два режима интерфейса

Один и тот же прогон показывается двумя способами; данные не дублируются, меняется только подача.

- `UiModeService` (`IsSimple` / `IsPro`) — единственный источник правды о режиме, сохраняет выбор в `UiOptions.ProModeByDefault`. ViewModel'и сети/настроек/дашборда подписаны на его `PropertyChanged` и пересчитывают свои `Show*`-флаги.
- `PlainLanguage` (`Core/Plain`) превращает `CheckResult` и вердикт в человеческий текст: статус словами, «что это значит», «что делать».
- `PlainFacts` собирает шесть фактов верхнего уровня (интернет-адрес, VPN/туннель, прокси, программы обхода, отклик сети) с тоном `good/warn/bad` и общим выводом о конфигурации.

## Вкладка «Глазами сайта»

Задача — не проверить компьютер, а показать, как он выглядит снаружи. Отдельный сервис, без участия
`CheckRunner`:

- `ISiteEyeService` / `SiteEyeService` — перебирает `GeoIpProviders` из настроек, первый внятный ответ
  побеждает; офлайн-режим вообще не ходит в сеть.
- `SiteGeoParser` — рекурсивный разбор JSON: ключи ищутся по имени, а не по схеме, потому что у
  `ipapi.is`, `ipwho.is`, `ipinfo.io` и `2ip` разные структуры (вложенные `connection`/`timezone`,
  ASN строкой `"AS396982 Google LLC"` или числом, флаги `true`/`"yes"`/`1`).
- `SiteViewAnalyzer` — чистые функции: собирает строки «визитной карточки», считает сигналы и их сумму
  (порог «похоже на VPN» — 50, «есть что записать в профиль» — 20). Часовой пояс адреса разрешается
  через `TimeZoneInfo` с возможностью подменить резолвер в тестах, поэтому расхождение поясов
  проверяется без зависимости от базы ОС.
- `SiteViewModel` — только подача: строки, сигналы, шкала, сырые HTTP-заголовки (в подробном режиме).
  Осмотр запускается сам при первом открытии вкладки (`EnsureLoaded`), повторный — кнопкой «Посмотреть».

Сеть не используется для «заглядывания» на сайты: на серверы ВК или Яндекса ничего не уходит,
это модель того, что они увидят, когда пользователь откроет сайт сам.

## Тестирование

`tests/NetworkChecker.TestKit` — общие двойники (`FakePlatformProbe`, `FakeHttpProbe`, `FakeCheck`, эталонные прогоны `Sample.CleanRun()/RichRun()`), чтобы тесты не ходили в сеть и не читали реальную ОС.

| Проект | Что проверяет |
|---|---|
| `Core.Tests` (235) | чекеры (включая детект SOCKS5/HTTP-прокси и API Xray/Clash на реальном loopback-листенере), раннер, вердикт, консенсус IP, парсеры, plain-язык, маскирование, настройки, эвристики hosts/маршрутов, разбор GeoIP и анализ «глазами сайта» |
| `Export.Tests` (29) | все семь форматов: содержимое, кириллица, валидность ZIP/Office-контейнеров |
| `App.Tests` (44) | ViewModel'и, переключение режимов, навигация, сравнение прогонов, экспорт через фейковый диалог, экран «глазами сайта», рендер всех шести экранов в headless-Avalonia |
| `Data.Tests` (11) | история прогонов (EF Core/SQLite), `settings.json`, повреждённый файл настроек |

Особенность: `Masking.Enabled` — процессный переключатель, поэтому `CheckRunner` восстанавливает его после прогона, а тесты внутри сборки идут последовательно.


## Требования к коду

- Предупреждения компилятора и анализаторов — **ошибки сборки** (`TreatWarningsAsErrors`,
  `EnforceCodeStyleInBuild`, `AnalysisMode=Recommended`). Сборка с предупреждением не проходит.
- Форматирование и стиль зафиксированы в `.editorconfig`: файловые namespace, `System`-using первыми,
  лишние `using` — ошибка (`IDE0005`).
- Культура форматирования: машинный вывод (JSON, CSV, Markdown, DOCX, XLSX, PDF) — всегда
  `InvariantCulture`; тексты интерфейса — с учётом локали пользователя.
- Беспараметровые утилиты (`PingTools`, `AsnLookup`, `TraceTool`) — статические классы: не тянут
  за собой экземпляры в DI и не создают иллюзию состояния.
- Одноразовые ресурсы: ViewModel'и с `CancellationTokenSource` реализуют `IDisposable`,
  окно вызывает `Dispose` при закрытии.


Обзор ограничений сети, весов и полноты: [REVIEW.md](REVIEW.md). Часть результатов в интерфейсе выделяется мышью и копируется Ctrl+C.


## Схема хопов и язык

`TraceGraph` нормализует числовой ASN и назначает детерминированный цвет из палитры; совпадения цветов разных ASN возможны. Пустой или невалидный ASN — серый. `TraceHopViewModel` подготавливает подписи, маскирует отображаемый IP и используется общей таблицей и горизонтальной схемой. Это схема последовательности, не геолокация. ASN получаем DNS-запросом к Team Cymru, а не из маршрутизатора, данные не гарантированы. И raw, и Ping-fallback записывают RTT ответов TTL Expired, если API предоставил время. Нет ответа не равно обрыву.

`Localizer` пока обеспечивает предварительный перевод навигации и части оболочки. Выбор хранится в `UiOptions.Culture`, применяется при старте; для остальных строк остаётся русский fallback. `CurrentUICulture` не меняется, чтобы язык интерфейса не выдавался за системный язык в модели сайта. Оставшаяся локализация и перевод сохранённых результатов и экспорта — отдельная работа.

В `SiteViewAnalyzer` разницу поясов сравнивают до округления; порог строго больше двух часов, неопределённый пояс не считается совпавшим. GeoIP возвращает IANA ID, .NET разрешает системный пояс; для Windows есть попытка преобразования IANA в Windows ID, при отсутствии базы выводится «неизвестен». Смещения вычисляются на момент отчёта с учётом правил DST, а не по текущему фиксированному UTC-значению. Windows-вариант всё ещё требует проверки на реальной системе.
