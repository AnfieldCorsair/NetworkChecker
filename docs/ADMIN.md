# Что даёт запуск с правами администратора

Статус этапа: по согласованию добавлены необязательная кнопка UAC и ограниченное ручное наблюдение WFP/ETW. Повышение прав и наблюдение никогда не запускаются автоматически. Подробности, ограничения и проверка на Windows: [OBSERVATION.md](OBSERVATION.md).

Остальные возможности ниже остаются идеями, а не обещанием уже реализованных функций. Доступ к некоторым данным может требовать не только администратора, но и разрешений политик Windows.

Ниже — список того, что можно включить, если запускать NetworkChecker от имени администратора (UAC).
Разбит по ценности: сначала то, что реально меняет вывод проверки, потом «глубина данных».

## 1. Что усиливает саму проверку

| Возможность | Что даёт | Чего стоит |
|---|---|---|
| **Raw ICMP** (`SOCK_RAW`, `ProtocolType.Icmp`) | Настоящий `traceroute` с TTL-хопами и временами вместо `Ping`-фолбэка; сравнение ICMP и TCP; расхождение само по себе не доказывает подмену | Windows разрешает raw-ICMP только администратору; часть провайдеров режет ICMP |
| **ICMP-спуфинг по-настоящему** | Сравнение TTL и времени ответа ICMP против TCP к тому же адресу; выявление подделанных ответов промежуточным узлом | Требует raw-сокета и «чистого» канала |
| **Полный список процессов** | `Win32_Process` через WMI: командная строка, подпись, родитель. Сейчас видно только процессы текущего пользователя | Медленнее (сотни мс), но даёт аргументы вместо «совпадения по имени» |
| **Полный файрвол** | Все правила, включая созданные другими пользователями и группами; пути правил и профили. Сейчас — только то, что отдаётся без прав | WMI/`Get-NetFirewallRule` под нагрузкой |
| **Службы и драйверы целиком** | Скрытые/защищённые службы (`WinDivert`, `Wintun`, `TAP`), их состояние и путь к драйверу | Нужен доступ к SCM с полными правами |
| **WFP-фильтры** (`FwpmFilterEnum`) | Снимок фильтров и callout может дать контекст, но сам по себе не доказывает перехват | Сложно: P/Invoke к `fwpuclnt.dll`, отдельный слой |
| **ETW-трассировка сети** | Сетевые события и возможный PID; связь с туннелем и перехватом требует отдельной проверки | Нужна сессия ETW (`Microsoft-Windows-TcpIp`), аккуратная остановка |
| **Снятие snapshot и откат** | Перед проверкой сохранить состояние прокси/hosts, чтобы сравнить «до/после» | Осторожно: любая запись в систему — только по кнопке |

## 2. Что расширяет «Сеть»

| Возможность | Что даёт |
|---|---|
| **Трассировка по каждому интерфейсу** | `SO_BINDTODEVICE`-аналог на Windows: сравнить маршрут через туннель и через физический адаптер — видно, куда реально уходит трафик |
| **Сниффер на 60 секунд** | Пассивный захват (pcap через `SharpPcap`/Npcap или ETW) с подсчётом: сколько трафика ушло в туннель, какие SNI запрашивались |
| **Проверка WFP-провайдеров** | Список установленных WFP callout-драйверов: кто перехватывает пакеты на уровне ядра |
| **Разбор NRPT-политик целиком** | Текущий код читает политики, но без прав видит не все ветки реестра |
| **Сброс кэша DNS и проверка после** | `ipconfig /flushdns` + повторная проверка доменов: отличить «кэш» от «блокировки» |
| **Чтение `netsh trace`-логов** | Готовый ETL-трейс Windows как источник для отчёта |

## 3. Сервисные вещи (аккуратно, только по явной кнопке)

- **Запрос прав из приложения**: кнопка «Перезапустить с правами администратора» (`Verb = "runas"`),
  с явным предупреждением, что дальше приложение видит больше.
- **Экспорт диагностического пакета**: логи + отчёт + `netsh winhttp show proxy` + `Get-NetAdapter`
  в один ZIP — для обращения в поддержку.
- **Установка как службы проверки по расписанию** — обсуждаемо, но это уже про «агент на парк машин».

## Что важно понимать

1. **Права меняют не вывод, а доказательность.** Вердикт без прав останется таким же по смыслу,
   но с меньшим числом подтверждений — и приложение должно это честно писать в отчёте
   («часть проверок недоступна без прав администратора»).
2. **UAC-запрос — это доверие пользователя.** Повышение прав только по нажатию кнопки, никогда
   автоматически, и в отчёте фиксируется, что прогон был с повышенными правами.
3. **Антивирус и EDR** реагируют на raw-сокеты и ETW-сессии. Нужен понятный текст в интерфейсе:
   что именно будет сделано, а не «нажмите и посмотрим».
4. **Ничего не пишем в систему** без отдельного подтверждения. Чтение — да, правки — только
   с явным «сохранить/восстановить».

## Предлагаемый порядок реализации

1. **Индикатор прав в интерфейсе** + строка в отчёте: «прогон выполнен без/с правами администратора».
   *(сделано: `EnvironmentSnapshot.IsElevated` — попадает в HTML- и JSON-отчёты)*
2. **Raw ICMP для трассировки** — код уже есть в `Core/Net/RawIcmp.cs`, нужно прокинуть признак
   «доступно/нет» в UI и в режим трассировки.
3. **Кнопка перезапуска с правами** (UAC) + текстовое объяснение. *(добавлено, требует проверки на Windows)*
4. **Полный список процессов и служб** (WMI с fallback на текущее поведение; пока не реализовано).
5. **WFP-провайдеры** — самый весомый аргумент, самая сложная часть.
6. **ETW/сниффер** — отдельная вкладка «Наблюдение», только по кнопке и с таймером. *(события ETW начаты; сниффер не реализован)*


**Актуализация:** наблюдение WFP/ETW показывает ограниченный однократный снимок фильтров и подписывается на события, но не доказывает перехват. Кнопка UAC и таймер добавлены; WMI, сниффер и ETW-корреляция не реализованы.
